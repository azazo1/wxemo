# 格式说明

## 磁盘布局

```text
business/emoticon/
  Persist/       表情密文
  PersistStore/  可能包含多个首尾拼接的图片
  Thumb/         缩略图, 文件名可能带 .thumb
  ThumbStore/    缩略图容器, 文件名可能带 .icon
  Temp/          临时数据
```

文件通常按名称前两位分桶. 不要把文件名后缀与输出片段编号混淆.

## 密文与明文

密文长度为 16 的正整数倍, 使用 AES-128-CBC,
密钥与 IV 都是 `MD5(f"{seed}{wxid}EMOTICON").digest()`.
有效的 PKCS#7 填充在切分前去除. 无效填充不会被强制删除.

| 格式 | 起始魔数 | 边界确定方式 |
| --- | --- | --- |
| PNG | `89 50 4E 47 0D 0A 1A 0A` | 顺序读取 chunk 长度, 到空 IEND 结束 |
| GIF | `GIF87a` / `GIF89a` | 跳过调色板与 sub-block 链, 到 trailer 结束 |
| JPEG | `FF D8 FF` | 跳过标记段和熵编码字节填充, 到 EOI 结束 |
| WebP | `RIFF` ... `WEBP` | RIFF 长度字段 |
| wxgf | `wxgf` | 未知, 保留输入剩余部分 |
| 其他 | 不限定 | 原样保留为 bin |

## 顺序切分与字节守恒

不能用 GIF 的第一个 `3B` 或 JPEG 的第一个 `FF D9` 作为结束位置,
这些字节可能出现在载荷内部. 各格式必须按照自身结构跳过载荷.

解析器从前到后处理输入, 确认一个完整片段后跳过其全部内容,
防止 PNG 的 IDAT 或 JPEG 的 metadata 内嵌图片被重复提取.
所有未识别的前缀, 中间区域和尾注都作为 bin 片段保留.

所有片段按顺序无缝覆盖原文, 没有重叠. 逐字节重新拼接应得到原始去填充明文.
空输入没有容器片段, 截断或结构损坏的输入仍保留所有字节.
边界解析不验证 PNG CRC, 也不代表图片可以成功解码.

## wxgf

wxgf 使用私有容器布局, 可能包含 HEVC NAL 单元.
`extract` 仍保留从 wxgf 头部开始的全部明文, 不依据内部魔数猜测整个容器的结束位置.
独立 `decode` 命令调用用户已有的原生媒体库, 输出 PNG/APNG.

已验证布局中, 字节 4 为头部长度, 字节 6 为布局版本 (0 或 2),
偏移 7, 9, 11 分别为大端 16 位画布宽度, 高度和额外帧数.
完整输出应有 `额外帧数 + 1` 个显示帧, 宽高采用原始画布而非 HEVC 对齐尺寸.
版本 0 的图片类型位于偏移 15, 版本 2 位于偏移 16:
`0x40` 为不透明图片, `0x81` 为 GIF 类容器, `0x82` 为带 alpha 的图片.
GIF 类也可能只有一帧, 多个 HEVC 分区不等于多个显示帧.

原生 `mode=2` 输出完整 APNG (或 PNG), 保留 RGBA, 时序和循环信息.
解码结果通过 chunk CRC, APNG 序号和尺寸 / 帧数校验后, 仅保留至 IEND 的标准图片数据.
边界和字段说明只针对已验证布局, 未知布局明确拒绝, 不作为通用的 WXGF 格式规范.
详见 [使用说明](reproduction.md).
